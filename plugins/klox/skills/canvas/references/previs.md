# Previs operations and production handoff

Read this for previs-backed images or clips, greybox timing reviews, or edits to a shared scene. Current tool schemas and `get_capabilities` are authoritative. Drama's storyboard and clips references own creative planning and the production gates.

## Write one shared scene

Use `addNodes` kind `previs` with `timeline`; update with `updateNodes[].timeline`, replacing the whole timeline. Keep unrelated actors, tracks and Shots when changing a scene. Read it again after user/agent edits rather than overwriting from an old copy.

Timeline v1 uses meters, seconds and degrees: floor coordinates x east/y north, height separate, yaw 0 north/90 east. The timeline includes duration, stage landmarks, actors, tracks and Shots. Actor types are humanoid (height and optional build), quadruped (species, shoulder height and length), and prop (box/cylinder/sphere dimensions). Associate actors with project asset IDs for correspondence; that association does not automatically feed asset reference images to a generator. Connect the appropriate asset nodes separately.

## Stand in a location set

A place that recurs is a location asset with a set (`save_asset` `identity.set`): bounds, wall/railing/open sides, openings and fixed furniture with stable IDs. Write `stage.location` = that assetId instead of copying the room into `stage.landmarks`. Put only this scene's own objects in `stage.landmarks`. Change a set fixture for this scene only with `stage.overrides` (`{fixture, hide: true}` or `{fixture, position?, yaw?, elevation?}`). Furniture that moves during the scene is a fixture prop: an actor `{id, kind: 'prop', label, color, fixture: '<fixture id>'}` with no shape or start. It takes the fixture's size and pose, replaces the fixture in this scene only, and needs its own id (the fixture's id stays taken). Never override a fixture you turned into a prop, and never copy its size or placement into a free prop. Never edit the set to suit one scene.

Walls the camera is ever outside of during a Shot are hidden for the whole Shot. Write `shots[].hide` (`wall:north`, `wall:south`, `wall:east`, `wall:west`, `ceiling`) only to choose differently.

Give an actor its character's `assetId` and leave `body` out: it takes the asset's body (`identity.body`). Write `body` only for a deliberate exception; a warning reports the difference.

If the location has no set yet, save one first (asset-design locations). For a one-off place with no asset, landmarks at explicit working sizes are still allowed. Do not infer physical dimensions from perspective in one image.

Evaluated tracks are move, motion, gaze, reach and transform. Use supported posture transitions and natural-duration bounds; movement and full-body motion may not overlap. A move key's yaw is allowed only at a stop and turning consumes dwell after arrival. To sit on the floor against a wall, stop the person with the back to the wall and play `slide_down_wall` (posture `sitting_floor`; `sit_floor` holds it, `stand_from_floor` gets up). A reach track moves one arm so the palm lands on a point or an actor anchor; the body does not lean or step, so stage the person within arm's reach and check the arm by eye. Reach places a hand; it does not prove a grip or a touch, so write the contact itself as a Shot note. Attach is rejected: choose supported staging or another production route.

A transform track moves one prop in world space (one track per prop). Each key writes `position`, `yaw` and optionally `elevation`, `pitch`, `roll` and `ease` (`linear` by default, or `easeInOut`, for the interval the key starts). Elevation is the center height minus half the prop's height: 0 stands it on the floor; a prop lying on its side goes below 0 (a 1 m chair on its back, 0.5 m deep: −0.25). Positive pitch lifts the front, positive roll lifts the right side, and the prop turns about its center, so tipping over a leg also needs the center's path in the keys. A free prop's first key equals its start exactly; to hold before moving, place that key at the moment the move begins. A fixture prop's first key is `{t}` alone and holds the fixture's pose until `t`; every later key writes a whole pose. Keep each angle's change between neighbouring keys under 180° and add a key in between for longer turns (0 → 135 → 270). Transform does not simulate gravity, contact or collisions and is not checked against walls: a pushed chair goes only where its keys say, a hand does not hold it, and a prop through a wall is not refused. Play it and check landing, floating and contact by eye. When `save_asset` reports `fixtureMotionReview` for a node, the fixture under a moving prop changed while its keys stayed put: replay the move from the new start and fix the keys if it no longer fits.

A Shot has an ID, scene start/end, aspect ratio and camera keys; camera key t is relative to the Shot start. When a Shot depends on an action the stand-ins cannot perform (an eye opening, a hand contact), still give it its real camera and window and write the action in `shots[].notes` (`{text, start?, end?}`, at most 3, times relative to the Shot start, default the whole Shot). The canvas shows notes over playback and never draws them into exports; editing them keeps exports current. A note declares the action unmodeled; it does not validate it. Shots can observe overlapping windows. A recurring setup and a finished edit shot are not the same identifier: keep Shot IDs stable and name the setup in production notes. The scene timeline does not specify final edit order.

### Camera moves

Write the camera the shot list names. Position changes need multiple camera keys unless the position follows an actor; focal-length changes always need multiple keys. A single key can follow a moving actor or pan/tilt toward an actor target; it is static only when its position and aim stay fixed. Key times are seconds from the Shot start. Position and aim use `ease` (`easeInOut` by default, or `linear`) for the interval the key starts; focal length always interpolates linearly.

| Shot list says                      | Write                                                                                                                                                                                                                                                                                                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Static                              | One key with a fixed position and target.                                                                                                                                                                                                                                                                                                                                                                       |
| Push in / pull out                  | Two keys on one line toward or away from an unchanged target. A slow push covers 0.3–1 m over the Shot; a sharp push covers it in under a second.                                                                                                                                                                                                                                                               |
| Pan / tilt                          | Same position in every key, target changes; or aim at an actor (`target: {actor, anchor: 'head'}`) to pan with it as it moves.                                                                                                                                                                                                                                                                                  |
| Pedestal / crane                    | Height changes between keys, target kept.                                                                                                                                                                                                                                                                                                                                                                       |
| Follow / tracking / dolly alongside | `position: {follow: {actor: '<id>'}, offset: [right, front, height]}` with the target on the same actor. The offset is in the actor's frame: +x its right, +y its front, height above the floor; it turns with the actor. `offsetSpace: 'world'` keeps the offset fixed on the plan (+x east, +y north) and stops the camera swinging when the actor turns. The camera follows the actor's path, not its steps. |
| Leading shot                        | Follow with a positive front offset, aimed back at the actor.                                                                                                                                                                                                                                                                                                                                                   |
| Reveal                              | First key aimed away from the subject or with it blocked; last key on it.                                                                                                                                                                                                                                                                                                                                       |
| Arc                                 | Three or more keys at one distance around the target.                                                                                                                                                                                                                                                                                                                                                           |
| Zoom                                | Focal length changes between keys; only when the shot list asks for a zoom rather than a move.                                                                                                                                                                                                                                                                                                                  |
| Settle into a follow                | Mix keys: a fixed key, then a follow key; the camera eases from one to the other.                                                                                                                                                                                                                                                                                                                               |

Follow positions accept people and animals only, with `follow: {actor}` and no anchor. Aim separately with `target: {actor, anchor: 'head'}` or another supported anchor. Follow height is above the floor, including when the actor sits or lies down.

Handheld shake is not modeled; name it in the clip prompt. After writing a move, play the Shot and compare the Screen map's start, middle and last samples with the shot list.

Fix all reported timeline issues and resubmit the change. Do not present a rejected timeline as validated or hide missing capabilities behind descriptions. An externally made animation can use the normal media route, identified as external reference rather than a solved Klox previs interaction.

## Read and review

`get_workflow` returns the timeline, each Shot's image/video export status, the node's diagnostics, what blocks a Shot's export (a camera inside a body, a root walking through a wall where there is no door or gap), and Screen-map samples at start, middle and last frame when available. A node that cannot be resolved (missing location, a location without a set, an actor with no body anywhere, an id clashing with the set) is marked `unresolved` and does not play or export; fix it before anything else. Use the samples for frame thirds, facing, side-up and approximate height; preserve borderline cases and unavailable results rather than inventing certainty.

Inspect playback for reveals, occlusion and important events between samples. Ask the user to review the whole-scene playback on the canvas (the clapperboard button): it plays only the Shots, in start order, so it runs as long as the Shots add up; scene time no Shot covers is left out and the label marks how much was skipped before a Shot; notes show over the picture. A computed map describes the stand-ins, not a guarantee that generated pictures or clips followed them. Inspect those outputs separately against the scene and assets.

Keep production notes on existing text nodes: scene/previs ID, Shot ID and window, dramatic purpose, planned cut length, sound source, chosen route, accepted keyframe and selected take IDs. Unmodeled actions go in `shots[].notes`, not in long disclaimers on text nodes. Export hash and file provenance are not universally exposed through MCP; use actual available evidence and mark missing dependencies unverified.

## Connect a Shot

- `previs → imageGen`, target `image`: the selected Shot's frame 0 as a layout guide, for that moment and camera.
- `previs → videoGen`, target `video`: the selected Shot's exported video as a blocking/camera reference.
- Set `connections[].shot` when adding the edge or `updateNodes[].previsShots` for an existing connection. The default first Shot is convenient only when it is actually the intended observation.
- Match the aspect ratio and reference window to the shot, and check model input duration, output duration, total reference limits and combination rules. A short planned cut does not justify an illegal reference file.
- `get_capabilities.referenceVideoRoutes[model].openingFrame` indicates the opening-picture input beside video: `firstFrame`, `image` with purpose `opening`, or null. Presence in this map does not prove voice compatibility or motion fidelity. Connect needed identity/state/voice assets through the allowed route, within its limits.
- `opening` is a prompted reference when on `image`, not a strict first-frame guarantee. At most one picture gets that purpose. Other timed keyframes have no purpose and are identified by clip time in the prompt.

A clip's scene window becomes a reference starting at 0; its generated take can have different actual timing. Keep final source in/out separate and review before editing. Extra model duration needs an explicit hold or usable coverage; no automatic tail-hold or arbitrary-time image-export option exists today. A separate short Shot can provide another moment's frame 0 if needed, within the existing contract.

## Export readiness and greybox cuts

Exports are made by the owner's browser and registered against the saved timeline. Connected stale Shots export after edits settle while the owner has the editor open. `run_node` / `run_nodes` cannot render them on the server today; a missing export returns `previs_render_required` with the required node/Shot. Check whether any task or batch was created before retrying; use the existing idempotency key for the same uncreated request, and respect batch retry/status semantics.

Have the owner open the editor when this is required, re-read actual export status, and then retry. If it stays unavailable, report the named Shot and error instead of repeatedly starting generation. Anonymous preview playback does not replace the owner's export process.

There is no direct previs-to-compose edge. `get_workflow` exposes export status, not a general list of downloadable previs export URLs, and there is no general MCP render/download command. Never invent one or scrape an unexposed file key from a guessed URL.

When exports are accessible through authorized browser/file operations or supplied by the owner, assemble the greybox cut locally and upload it as source material with `addFileNodes`; combine accessible clips and temporary dialogue cards in edit order. Use `import_node_output` only if it is the actual result of an appropriate existing output node. Keep timing annotations out of the clean reference videos used for final generation.

If accessible exports are absent, review the owner's Shot playback against a written cut list and sound windows. Report that the assembled edit remains unverified; do not present separate scene playback as a finished animatic. Do not spend final-video credits merely to bridge this tool gap.

## Changes

A relevant timeline/Shot change, or a change to the set or body it reads, invalidates affected exports; `save_asset` lists the previs nodes a set or body change touched and any problem it brought in. Old generated images and takes are still stored and do not update automatically. Recheck the affected visual inputs, take selection and cut mappings using recorded sources and available current/outdated indicators. Renaming a Shot or node alone does not mean the picture must be regenerated.
